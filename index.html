1. 에이전트가 읽는 작업 계약 문서

2026.09 – 현재

문제
작업 폴더와 문서가 여러 개라 새 AI 세션이 옛 문서를 현재 상태로 읽을 수 있었습니다.
구조
시작 문서는 AGENTS.md 하나입니다. 현재 상태는 CHECKPOINT 한 곳에만 두고, 다음 할 일은 짧은 HANDOFF에 둡니다. 배포, DB, 수집기 문서는 목록으로 연결해 필요할 때만 읽게 했습니다. 예전 작업 폴더에는 "여기는 기준이 아니다"라는 안내만 남겼습니다.
규칙
작업마다 바꿀 파일과 변경 구간을 정하고 그 경로만 커밋합니다. 사용자 변경을 지우는 reset, 강제 푸시, 훅 우회는 금지입니다. missing이나 error를 0, 다른 시즌 값, 추정 성공으로 채우지 않는다는 fallback 금지도 계약에 적었습니다.
역할
설계, 구현, 대용량 탐색, 독립 검토, 문구 다듬기를 모델마다 나눴습니다. 지정한 모델이 응답하지 않으면 다른 모델로 조용히 대신하지 않고 미완료로 알립니다. 한 파일은 한 에이전트만 고칩니다.

2. 무결성 원칙을 코드에서 지킨 예

ERCraft · 루미아 덱

실패 가시성
경기가 끝나기 전에 받은 불완전한 상세(24명 중 3~21명)를 완성본처럼 쓰지 않고 다시 받게 했습니다. 원본이 없어 되살릴 수 없는 경기(약 3.6%)는 "기록 부족"으로 표시합니다. AI 분석 문장의 수치가 원본과 다르면 그 문장을 보여 주지 않습니다.
원자성
검색 제외 기능의 첫 배포가 배포 스크립트 버그로 중간에 멈췄을 때, 자동으로 원래 상태로 돌아갔습니다.
멱등성
AI 플레이 테스트는 끝난 판을 바로 파일로 저장합니다. 다시 돌려도 끝난 판은 건너뛰고 남은 판만 돌립니다.
일관성
가장 큰 테이블을 압축한 뒤 표본 2,000행의 해시를 비교해 내용이 그대로인지 확인했습니다.
SSoT
검색 제외는 닉네임이 아니라 내부 계정 단위로 걸어, 닉네임을 바꿔도 풀리지 않습니다.

6. AI가 게임을 직접 플레이하는 테스트 도구

2026.10.18–21

문제
덱빌딩 게임(루미아 덱)을 Phaser와 TypeScript로 만들면서, 고칠 때마다 사람이 수십 판을 해 볼 수는 없었습니다. 난이도 목표는 "처음 하는 사람은 1막 후반, 해 본 사람은 3막에서 막힌다"였습니다.
만듦
AI 모델이 실제 게임 엔진에서 한 판을 처음부터 끝까지 플레이하게 했습니다. 지도, 카드, 상점, 휴식처럼 사람이 하는 선택을 모델이 JSON으로 답합니다. 규칙에 안 맞는 행동은 거절하고 횟수를 셉니다. 판이 끝나면 모델이 재미와 공정성 등을 점수로 남깁니다.
운영
여러 판을 동시에 돌리고, 끝난 판은 바로 파일로 저장해 중간에 끊겨도 이어서 돌립니다. API 오류가 7번 이상 난 판은 결과에서 따로 뺍니다. AI 판과 별도로 봇 160판으로 승률을 잽니다.
판단
10월 19일 하루에 21차까지 돌렸습니다. 그래도 AI 점수만 믿지는 않았습니다. 직접 해 보니 첫 판에 3막까지 여유 있게 깨져서, AI 공정성 점수를 올리려고 넣었던 완화 장치를 일부 뺐습니다.

7. 배포 뒤 생긴 장애

2026.10.27

증상
검색 차단 기능을 배포한 뒤부터 시즌 통계 API가 모든 요청에 500 오류를 냈습니다. 그날만 약 3,500회입니다.
발견
검색 속도를 조사하다 서버 로그에서 처리되지 않은 오류 수를 세어 보고 찾았습니다.
원인
새로 넣은 함수에 인자 순서를 잘못 넘겼습니다. 이 경로의 테스트가 이미 깨져 있어서 버그를 걸러내지 못했습니다.
대응
인자를 고쳐 같은 날 배포했고, 정상 응답(200)을 확인했습니다.
남은 과제
원인은 배포 기록에 남겼습니다. 깨져 있던 테스트가 새 버그를 가릴 수 있어서, 그런 경로는 배포 뒤 실제 요청으로 한 번 더 확인하는 절차를 넣으려고 합니다.

AI로 일하는 방식

AI로 일하는 방식

코드는 대부분 AI가 씁니다. 저는 요구사항을 정하고, 결과를 확인하고, 배포 여부를 판단합니다. 코드 한 줄 한 줄을 다 외우지는 못하지만, 구조와 왜 그렇게 만들었는지는 설명할 수 있습니다.

받지 않은 제안

다국어 AI 분석을 처음부터 외국어로 만들자는 제안은 받지 않았습니다. 그러면 한국어 기준으로 만든 숫자·근거 검사를 건너뛰게 됩니다. 한국어로 먼저 만들어 검사를 통과시킨 뒤 번역하게 했습니다.

결과는 실제 화면에서 확인

테스트 통과로 끝내지 않고, 배포 뒤 실제 API 응답과 화면에서 바뀐 것을 확인합니다. 검색 차단 기능은 API 4개 경로와 화면을 직접 봤습니다.

AI 결과를 그대로 믿지 않기

요청 범위 밖의 코드가 같이 바뀌었는지 diff로 먼저 확인합니다. 자동 수정 루프가 원래 깨져 있던 테스트를 맞추려다 엉뚱한 코드를 바꾼 적이 있어서, 지금은 그런 테스트를 자동 수정 대상에서 빼고 돌립니다.

같은 일을 여러 모델에 시켜 보기

카톡 비서의 비교 명령은 연결된 AI에 같은 질문을 동시에 보내고, 각 답에 걸린 시간을 보여 줍니다. 게임 테스트도 모델 3개로 같이 돌렸습니다. 모델 의견이 같아도 실제 동작을 직접 보고 결정합니다.
